# Agent Lab

Небольшая учебная страница на русском языке о работе с агентами. Все примеры вымышлены. Чистые HTML, CSS и JavaScript; установка зависимостей и сборка не нужны. Внешних шрифтов, аналитики, форм отправки и сторонних запросов нет.

## Просмотр

Откройте `index.html` в браузере. Для локального HTTP-просмотра из корня проекта: `python -m http.server 8022 --bind 127.0.0.1`. Адрес: http://127.0.0.1:8022/ . Для удалённого просмотра владелец использует закрытый предпросмотр BB Connect, который требует его сессии BB.

## Точный набор для публичного репозитория

- `index.html` — страница.
- `styles.css` — адаптивное оформление.
- `script.js` — переключение трёх учебных примеров.
- `.nojekyll` — публикация готовых статических файлов.
- `.gitignore` — исключение локальных проверок и служебных данных.
- `README.md` — эта инструкция.

Папка `local/` содержит только локальные проверки и снимки. Она исключена из Git и не предназначена для публикации. Никакие другие папки Documents в репозиторий не входят.

## GitHub Pages — после явного разрешения владельца

Инструкция сверена с официальной документацией GitHub 12 ноября 2026 года:

- [Возможности и тарифы Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages): на GitHub Free Pages доступен для публичных репозиториев. Код, README и история коммитов такого репозитория будут общедоступны.
- [Источник публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site): для готового статического сайта подходит публикация из ветки.

План: создать публичный репозиторий `Agent-Lab-Site` в подтверждённом аккаунте владельца, отправить только перечисленные выше шесть файлов из локального Git, затем выбрать Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/ (root)` → Save. При недоступном имени не менять существующий репозиторий: согласовать новое имя. Платные ресурсы и собственный домен не нужны. До прямого разрешения не создавать репозиторий и не отправлять коммиты.

После публикации: дождаться успешного развёртывания Pages, открыть URL из настроек, проверить три примера, якоря и отсутствие горизонтальной прокрутки на телефоне и компьютере. До этого живая страница не считается проверенной.

## Как обновлять

Самый простой способ после публикации: в GitHub открыть нужный файл → карандаш Edit → изменить текст → Commit changes в `main`. Pages опубликует обновление автоматически. Для изменения оформления редактируйте `styles.css`, для учебных примеров — `script.js` (начальный пример также в `index.html`).

При работе локально: изменить файлы, открыть страницу и проверить телефонные ширины; затем `git add index.html styles.css script.js README.md .gitignore .nojekyll`, `git commit -m "Update learning page"`, `git push origin main`. Отправка изменений обновляет публичный сайт: выполнять её только в согласованном объёме.

## Проверки перед публикацией

Ширины 360, 390, 412 и 1440 px; читаемость, переносы, прокрутка, три переключателя, ссылки к примерам и наверх, клавиатурный фокус. Фактический отчёт и изображения хранятся локально и не публикуются.
